# 字符串能力待完善

本文记录 tap 当前字符串实现的能力边界、已知限制和后续建议。当前 `string` 主要面向
UTF-8 文本，不是可以保存任意字节的二进制字符串。

## 当前已经支持

- 字符串字面量、变量、常量、函数参数和返回值。
- `string` 固定长度数组以及 `Vec<string>`。
- `\\n`、`\\t`、`\\\\`、`\\"` 四种字面量转义。
- `.len()`：返回以 UTF-8 编码计算的字节长度。
- `.byte_at(index)`：按字节读取，返回 `u8`。
- `.slice(start, end)`：按字节偏移复制左闭右开区间。
- `==`、`!=`、`<`、`<=`、`>`、`>=` 内容比较。
- `+` 字符串拼接。
- `std.byte_vec.ByteVec` 和 `std.string_builder.StringBuilder`。
- `std.parse` 中的整数/浮点解析和格式化。
- `std.json` 中的 JSON 字符串转义和反转义。
- 文件、环境变量、进程管道和 TCP 接口中的文本传递。

## 主要缺口

### 1. 字符串表示和二进制数据

当前 Runtime 使用以 NUL 结尾的 `char *` 表示 `string`：

```text
string = char *
```

由此产生以下限制：

- 不能保存嵌入的 `\\0` 字节。
- `ByteVec.to_string()` 遇到 NUL 会终止程序。
- 文件、管道和文本网络 API 不能安全处理任意二进制内容。
- `.len()`、比较和拼接都依赖 `strlen`。
- 外部函数返回 NULL 字符串指针时没有安全的空值检查。
- 拼接、切片、格式化等 Runtime 字符串会一直保留到进程退出，缺少单个字符串释放能力。

长期可以考虑引入长度携带的表示：

```text
struct String {
    data: *u8,
    length: uint,
}
```

这会改变现有 FFI 和 ABI。较稳妥的过渡方案是保留当前文本 `string`，另外增加独立的
`Bytes` 类型，用于文件、管道、Socket 和任意二进制数据。

### 2. Unicode 和 UTF-8

当前操作全部以原始字节为单位：

- 没有 Unicode 码点或 `rune`/`char` 类型。
- 没有字符数量查询。
- 没有按码点读取或按码点切片。
- 没有 UTF-8 合法性验证。
- `slice()` 可以从一个多字节字符中间切开，产生无效 UTF-8。
- 没有大小写转换、Unicode 分类、大小写无关比较或规范化。
- 没有用户感知字符（grapheme cluster）处理。

需要先明确语言政策：是只承诺“UTF-8 字节串”，还是由标准库提供严格的 UTF-8 文本操作。
推荐先增加显式的 UTF-8 解码/验证 API，再增加码点级操作，避免让 `.len()` 的现有字节语义
产生歧义。

### 3. 常用字符串操作

标准库目前没有以下基础 API：

- 查找：`contains`、`find`、`rfind`、`starts_with`、`ends_with`。
- 分割和组合：`split`、`join`、`lines`。
- 清理和变换：`trim`、`trim_start`、`trim_end`、`replace`、`repeat`、`reverse`。
- 字符串索引语法：目前只有 `.byte_at()`，没有 `text[index]`。
- 可变字节替换：只能通过 `ByteVec` 或 `StringBuilder` 间接完成。

这些能力不一定需要修改底层 ABI，大多数可以先用 tap 标准库实现。

### 4. 字面量和转义

源代码字符串目前只稳定支持四种转义。尚未提供：

- `\\r`、`\\b`、`\\f`、`\\/`、`\\0`。
- `\\xNN` 字节转义。
- `\\uXXXX` 或 `\\u{...}` Unicode 转义。
- 原始字符串和明确的多行字符串语法。

当前未知转义序列会静默去掉反斜杠，例如 `\\q` 会变成 `q`。这会隐藏源代码错误，应该
改为词法错误，或者至少提供明确的兼容模式。

### 5. 格式化和类型转换

当前数值转换主要由 `std.parse.format_i64` 和 `format_f64` 提供，仍缺少：

- `bool`、其他整数宽度和枚举的统一转字符串 API。
- `StringBuilder.append_i64`、`append_f64`、`append_bool` 等类型化追加函数。
- 字符串插值，例如 `"name={name}"`。
- 通用格式化接口，替代手工创建格式串。
- `print`/`printf` 格式占位符与参数的静态检查。

特别是格式串和变参参数目前由调用者保证匹配，`%s` 与非字符串参数不匹配时可能导致
未定义行为或运行时崩溃。

### 6. 错误处理和安全性

`.byte_at()` 和 `.slice()` 的越界行为是打印错误并终止进程，不能由调用者恢复。需要区分：

- 程序员错误：可以继续使用当前的终止行为。
- 外部输入导致的边界错误：更适合提供 `Result` 或 `Option` 版本。

建议增加安全变体，例如 `try_byte_at`、`try_slice`，或者明确规定所有字符串边界错误都属于
不可恢复错误并保持现状。

还需要补充 NULL 指针、超大字符串、长度/容量溢出和无效 UTF-8 的统一处理策略。

### 7. 性能和内存

当前实现存在以下性能特点：

- `.len()` 每次都从头扫描，复杂度为 O(n)。
- 比较使用 C 字符串扫描。
- 每次 `.slice()` 都复制内容。
- 链式 `+` 会产生多次临时字符串分配。
- Runtime 字符串统一延迟到进程退出时释放，长时间运行程序会持续增长。
- 没有字符串视图（`data + start + length`）或容量复用机制。

可以按优先级逐步增加：保存长度、提供字符串视图、为 Builder 提供格式化追加，以及在
明确所有权模型后增加引用计数或显式释放。

## 建议实现顺序

### 第一阶段：不改变现有 ABI

1. 修正未知转义的处理，并补齐常用的 `\\r`、`\\b`、`\\f`、`\\0` 转义。
2. 增加 `contains`、`find`、`starts_with`、`ends_with`、`trim`、`split`、`join`、`replace`。
3. 增加 `StringBuilder` 的整数、浮点和布尔追加接口。  ✅ 已完成
4. 增加 UTF-8 校验和码点读取 API，明确 `.len()` 继续表示字节长度。
5. 为越界和无效 UTF-8 增加回归测试及可恢复 API。

### 第二阶段：完善文本模型

1. 增加 `char`/`rune` 类型及码点级索引、切片。
2. 增加 Unicode 大小写、分类和规范化支持。
3. 增加字符串视图，减少切片复制。
4. 增加格式化和字符串插值。

### 第三阶段：支持二进制和长期运行

1. 引入 `Bytes` 或长度携带的 `String` 表示。
2. 让文件、管道和 Socket 的字节 API 不再依赖 NUL 结尾。
3. 设计明确的字符串所有权、借用和释放规则。
4. 在 ABI 稳定后优化长度缓存、分配和拼接性能。

## 建议补充的测试

- 含 `\\0` 的字节串和 `ByteVec` 转换行为。
- 非法 UTF-8、四字节 UTF-8、代理项和码点边界。
- `slice()` 切在多字节字符中间时的行为。
- 空字符串、极长字符串、拼接溢出和容量扩展。
- 未知转义、各类转义和多行字符串。
- NULL 外部字符串返回值。
- 文件和管道中包含二进制 NUL 的数据。
- `print` 格式串与字符串参数类型不匹配时的诊断。
